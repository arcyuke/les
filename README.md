# ЛЕС — сайт и бронирование

Каркас сайта в светло-жёлтых тонах. Главная, «О нас», услуги и тарифы, площадки, отзывы, контакты, онлайн-заявка и политика конфиденциальности. Фотографии, видео и отзывы добавляются позже через админку.

## Запуск

Нужен Node.js 22 или новее. Сторонних npm-зависимостей нет.

```sh
npm run build
npm start
```

Открыть `http://localhost:3000`. Админка: `/admin.html`. Для проверки: `npm test`.

Можно разместить только содержимое `dist/` на статическом хостинге. Главная и остальные страницы работают без JavaScript; JavaScript добавляет фильтры, мобильное меню, редактор и форму. Сервер Node.js нужен именно для заявок и Telegram. На статическом сайте без сервера форма не сообщает об успешной отправке и предлагает связаться по телефону.

## Админка через GitHub

1. Создать fine-grained token только для репозитория `arcyuke/les`, с правом **Contents: Read and write**.
2. Открыть `admin.html`, ввести токен. Он хранится только в памяти вкладки. После закрытия или выхода нужно войти заново.
3. Редактировать тексты, цены, фото, видео, отзывы, контакты, подвал. Можно добавлять, скрывать, удалять и переставлять элементы. Для видео пока поддерживаются прямые HTTPS-ссылки на MP4/WebM, а не ссылки на страницы Google Drive или роликов ВК.
4. Нажать «Сохранить в GitHub». Контент, новые фото и готовые HTML-страницы записываются одним коммитом. Изменение ветки выполняется без force. Если ветка изменилась после входа, сохранение остановится; черновик можно скачать в JSON.
5. Хостинг необходимо один раз подключить к ветке `main` для автоматической публикации изменений. GitHub-коммит сам по себе не запускает сайт и не настраивает хостинг. При ручном размещении потребуется обновить файлы на хостинге.

В GitHub лежит только публичный контент сайта. Заявки, телефоны посетителей, список получателей Telegram и секрет бота в репозиторий не записываются. Не вставляйте секреты в поля редактора.

## Онлайн-бронирование и Telegram

Форма отправляет **заявку**, а не автоматически подтверждённую бронь. Администратор связывается с клиентом, согласовывает цену, время и переводит заявку в статус «Подтверждена». На этапе каркаса подтверждённая заявка занимает площадку на весь выбранный день. До введения длительности программ так исключаются пересекающиеся мероприятия. Две площадки бронируются независимо. Заявки в ожидании не блокируют дату.

Для рабочего запуска:

1. Разместить Node-сервер за HTTPS (можно через приложенный Dockerfile). **Один процесс и одна реплика**, постоянный диск для `DATA_DIR`. Текущая файловая очередь не предназначена для нескольких реплик.
2. Задать переменные из `.env.example` через настройки хостинга. Node не читает `.env` автоматически; для локального запуска можно использовать `node --env-file=.env server/index.mjs`.
3. Создать отдельного бота через BotFather. Сохранить его токен в `TELEGRAM_BOT_TOKEN` на сервере. Не отправлять его в GitHub. Этот сервер использует getUpdates; у выделенного бота не должно быть другого обработчика обновлений или активного webhook.
4. В админке открыть Telegram → создать персональную ссылку. Получатель открывает её, нажимает «Старт». Нажать «Обновить список» и включить переключатель этого человека. Повторить для остальных. Подключение по одному username без запуска бота не работает. Приглашения одноразовые, действуют 24 часа; новые получатели по умолчанию выключены.
5. В разделе «Конфиденциальность» заполнить оператора и финальный текст политики, затем отметить готовность. Заготовка не является готовым юридическим документом.
6. Указать `ALLOWED_ORIGINS` — точный адрес сайта с протоколом. Если сервер отдельный, прописать его HTTPS-адрес в «Подключение сервера». Токен GitHub будет передаваться этому доверенному серверу для проверки права управления `arcyuke/les`.
7. Включить `BOOKINGS_ENABLED=true` после настройки политики, хранения данных и получателей. Перезапустить сервер с актуальным содержимым `dist/`.

Заявка сначала сохраняется на диск. Ошибка Telegram не теряет заявку; уведомления доставляются повторно с задержкой. Отправка имеет семантику at-least-once: при аварии между отправкой и сохранением отметки возможно повторное уведомление. Номер заявки помогает отличить повтор. Если получателей ещё нет, заявка остаётся в админке без Telegram-уведомления. При работе через reverse proxy лимит запросов по умолчанию общий для его IP; адаптируйте доверенную обработку IP на выбранном хостинге.

Необходимы регулярные резервные копии приватной папки `DATA_DIR`. Перед публичным запуском нужно согласовать срок хранения и удаление заявок, настройки защиты от спама и окончательную политику обработки данных. Сейчас онлайн-приём по умолчанию выключен.

- Реальные фотографии, видео и отзывы. Места для них предусмотрены, вымышленных отзывов нет.
